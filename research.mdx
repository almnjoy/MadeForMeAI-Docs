How and where I actually research: the sources, the order I hit them, and the checks I run before I trust an answer. Packaged so you can run the same playbook instead of guessing.

## What a research path is

A written, repeatable playbook for one kind of question. Not "do research," but: the exact sources for this domain, the order to hit them, what each one is trusted for, the cross-checks before an answer counts, and the shape the output takes. The kind of process a good senior engineer runs on instinct, written down so it survives contact with a Tuesday.

## Why source order beats model quality

Most bad answers don't come from a bad model. They come from starting at the wrong source, trusting a claim that was never checked, or averaging two sources that disagree instead of surfacing the conflict. A path fixes the process:

- **Primary sources first**: the spec, the docs, the filing, the changelog. Commentary comes after the thing itself.
- **Vendor claims get verified**: marketing pages state intentions; community reports and issue trackers state reality. A path checks both and says which one it believes.
- **Dates get checked**: half of what's wrong on the internet was right two years ago. Every load-bearing claim carries a freshness check.
- **Disagreements get surfaced**: when good sources conflict, the output says so and says why, instead of quietly picking one.

## Packaged to run

A path ships as a playbook an agent can follow: give the question, and the research runs the defined sources in the defined order, applies the checks, and returns the defined output format with its receipts. You read a verdict with evidence, not twelve open tabs. The same path runs next quarter and is comparable to this quarter, because the process didn't drift.

## Where they come from

Every path here is extracted from research I actually run: evaluating a vendor, sizing a market question, digging out why a system misbehaves. If I wouldn't bet my own build on the process, it doesn't become a path.

## Status

In daily use inside my own builds: the research legs of the [Kalshi bot](/kalshi-bot) and the digging behind every project on this site run this way. Packaging paths for specific domains happens per request.
